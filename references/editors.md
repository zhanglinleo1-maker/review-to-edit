# 工程输出与验证规则 v0.5.11

## 1. 类型、版本与证据边界

下表是本流程的输出策略，包含此前项目的用户实测路线，不是厂商对所有版本的兼容承诺。新项目继承路线经验，不继承旧工程验收通过；Windows实测不自动等于Mac实测。执行时核对目标版本与现有导出器。

FCP7 XML（常见xmeml根）与现代FCPXML是不同格式，不能改后缀代替转换。FCPXML是交换格式，不是原生Final Cut Library。5.9兼容草稿不是当前剪映原生工程。.prproj必须由Premiere或真实验证的生成器产生，没有能力就给交换路线，不重命名冒充。

### 1.1 目标环境：先检测，必要时补问

分别记录目标剪辑软件、目标操作系统（Windows/macOS等）、软件实际版本号，不以含糊的“版本”同时指代系统、软件号或创作方案版数。

- 用户已指定的软件/交付电脑优先，已知不重问。软件未知时集中问目标软件；本机装了某款软件不代表用户选择它，不能只因可检测就替用户决定软件。
- 软件已选后，在当前权限范围内优先只读核查本机系统及所选软件的安装信息。范围限定为该软件已知安装/应用登记位置和主程序/应用包版本元数据；版本号应来自可靠元数据，不凭安装目录、旧工程或历史记忆猜测。不默认全盘扫描、打开编辑器、升级安装、修改配置或接管电脑。无访问能力如实记录，必要时询问，不承诺总能查到。
- 确认正在检测的是用户目标电脑还是远程/沙箱/云端执行环境；后者不能冒充用户本机。未指定跨机且可靠检测到用户本机时，可采用“本机检测默认”，在集中需求摘要中告知，例如“检测到本机为Windows，已安装剪映专业版××，默认按此环境交付；如需在其他电脑使用请说明”。这不是新的审批节点，也不标为用户明确确认。
- 用户明确在另一台电脑精剪/交给他人时，不用执行主机检测代替目标信息；只补问缺失的目标系统，软件版本号仅在影响工程格式、效果映射或兼容时需要。多版本并存且无法确定实际使用版本、检测失败或信息冲突时同样集中补问必要项；不要让用户为无关小版本号反复查找。
- 项目记录保留软件/目标系统/版本号、检测来源与时间、属于用户指定还是检测默认、未知/冲突项。安装存在或版本可读不证明导出器支持、编辑器导入或保存重开通过。前期创作不因非必要版本信息缺失停工；输出依赖版本的工程前核实相关兼容约束，无法核实则说明适配范围及待验，不凭默认宣称已验收。

## 3. 剪映Windows三条路线

### A. 兼容草稿主路线

只读配置确定实际自定义草稿目录，不写死AppData默认路径。多用户/多配置或读取失败才询问设置中的位置；核对配置字段及现有结构，目录存在不代表正确。不要改已有草稿作试验。

生成独立新文件夹、JSON、封面和资源，检查draft_id/name、路径、时长、轨道与素材引用。用户已要求交付本机可用的剪映兼容草稿时，放入只读检测所得的当前草稿目录是交付的一部分：权限允许则默认完成，不另问是否安装，也不只给工程包/安装脚本让用户自行复制；同时保留独立交付副本。只做方案/Demo、跨机交付或用户明确仅输出文件时不自动放入本机目录；目录无法可靠确定或权限受限时说明，补问必要信息或交可用文件，不猜路径、不绕过权限。此落地原则也适用于其他系统上已获准且适配可用的剪映兼容草稿，不把Windows路径/字段套给Mac，更不将Mac的FCPXML路线改成自动安装草稿。

目标已存在采用新版本/唯一名称，不覆盖删除；只更新新草稿路径字段，复制后回读校验目录、工程及依赖/原素材引用。不直接改根索引，如确需索引操作另说明并取得明确许可；不自动启动、关闭或接管剪映。交付说明记录实际落地路径和成功/受阻状态，不能只检查独立输出目录就说已放入草稿目录；已放入不等于首页已显示或打开成功。

用法：首页找新草稿→打开→当前版本保存升级→关闭重开。未显示可刷新或重启，也可备用路线；不终止用户正在编辑的应用，不删除旧项目。未查看UI时标“已复制，显示/打开待验收”。

#### Windows剪映已验证适配：11.6.0.14552

2026-10-17，用户实测素材箱/原生成轨道定位及片段缩放位移复位有效；这是此版本的方法验证，不是所有剪映版本或其他软件兼容保证，也不代表每个新工程UI已验收。

生成时按真实源路径统一登记原视频/照片，素材箱及轨道默认显示原素材完整文件名（含扩展名），不添加S004等分镜编号或自定义前缀。同一原片多个区间仍沿用原文件名，同名不同路径用内部ID和映射区分，不擅自重命名。分镜编号只留在脚本/分镜表及内部映射，关联原文件名、完整路径、源入出点与时间线位置；不是代理、快捷方式或媒体文件名。该命名原则适用于全部目标软件，不改磁盘文件名和必要内部ID/引用关系。

剪映本适配的materials.videos[].material_name及draft_materials登记extra_info使用原文件名；material或segment已有用于显示的name字段时也同步原文件名，不为无此字段的片段虚构显示字段，轨道类型/轨道名称和字幕文字不改。prepare仅作用于获准的新生成工程/独立副本，audit只读检查这些命名，不追溯批量修改用户历史工程。关系仍为segments[].material_id→materials.videos[].id；本次本地materials.videos[].material_id为空字符串；local_material_id→draft_meta_info.json中draft_materials的登记id。登记真实原文件名、路径、尺寸、源视频全时长，照片展示时长不冒称物理源时长。轨道能播、素材箱能定位、轨道能定位是不同检查项，不将这些字段规则未经验证套给音频或其他格式。

默认构图保留完整源画面，用片段clip.scale等比缩放（X/Y相同）、clip.transform位移；该写法在本次界面可调整及复位，缩放复位为1/1、位移为0/0。画布比例不同复位可能留边，不等于画面必须铺满。素材级非完整画面crop不再作为默认构图，不禁止裁切本身；缩放位移会同时影响左右可见范围，不等于任意边界裁切，其他裁切/蒙版需另验。恢复全画面可能重新暴露隐私，发布前仍核查，但不能未经同意固化媒体来替代。

使用[登记与可恢复构图组件](../scripts/jianying_editable.py)：新生成器在序列化前调用prepare_draft(content, meta, sources, transforms)，或对独立解码副本使用prepare命令，再audit；无需每次重新编写字段补丁。sources由已核查源清单提供，不能从预览片段反推原片。组件保留未要求变更的轨道/音频/字幕；遇已有非完整crop或需改的片段已有关键帧时拒绝静默覆盖，须明确重建策略后另处理，不自动把用户精修清零。按源路径缓存登记与可达性检查，不重新识别或渲染。

组件只做JSON层后处理/校验，不是完整编辑器或加密格式编解码器；CLI输出是独立中间副本，不会安装草稿。当前版本保存的非明文工程可用匹配版本的已验证读写工具（本次jy-draftc在副本上往返通过），工具路径和软件目录由当前环境探测，不写死旧项目路径，不捆绑/盲目安装。不能解析时明确阻塞，不用旧模板覆盖当前工程。实际编解码往返、封面和依赖打包、软件打开仍由目标适配器完成，不把JSON读回冒称原生编解码/界面通过。

组件调用格式：

```text
python <Skill绝对目录>/scripts/jianying_editable.py audit --content <解码content绝对路径> --meta <解码meta绝对路径> --profile windows-jianying-11.6.0.14552
python <Skill绝对目录>/scripts/jianying_editable.py prepare --content <新生成或最新保存副本的解码content> --meta <解码meta> --sources <已核查源清单JSON> --transforms <片段变换JSON> --output <全新独立中间目录> --profile windows-jianying-11.6.0.14552
```

sources是列表，每项含path（完整原片绝对路径）、kind（video/photo）、width、height；video另有duration_us（源全时长，微秒）。照片使用生成器已有的格式展示容器时长，不编物理源时长。transforms可省略，是segment_id到{scale:等比数值,x:位移,y:位移}的映射，不强套测试数值。audit没有sources时只能检查关联及内部范围，不能确认引用的是获准原片；输出分别记录。变速、复杂裁切、关键帧、旋转/特殊比例等仍需目标适配器核查，脚本通过不证明这些效果或解码可播放。

### B. FCPXML备用路线

历史Windows实测导入工程默认筛选.prproj时，可在文件名框输入`*.fcpxml`显示文件。这是筛选技巧，不是所有版本支持的保证。无法显示/解析先查版本、格式、路径，不反复换后缀。

src使用合法file URI，处理Windows盘符/反斜杠，中文、空格、特殊字符正确编码；解码后检查真实文件。Mac同样需合法URI。特定导入器不兼容时使用可恢复派生路径/重链接，保留映射，不移动改名原片。硬链接不是独立素材备份。

历史适配器使用resources/library/event/project/sequence包装；按实际DTD与目标版本验证，不将该经验当成所有软件唯一格式。字幕节点存在不等于目标显示、样式保留或原生Caption轨成功。

### C. Premiere中转兜底

FCP7 XML导入Premiere→导入并放置SRT→保存.prproj→剪映导入。Agent不能操作Premiere时交XML/SRT和简短步骤，不声称.prproj已生成。已实测路线无需每次重新研究，但新文件的源区间和媒体引用仍检查。

## 4. 单一时间线与映射要求

### 4.1 通用混合画幅默认：清晰等比前景＋同素材模糊背景

适用所有目标软件（包括剪映、Premiere、DaVinci Resolve、Final Cut Pro）、系统及画布方向。视频/照片的显示宽高比与当前画布不一致时，默认上层显示清晰的原素材、保持原始比例并等比适配、尽量完整保留主体和画面；底层以同一素材同一源区间等比铺满画布并模糊，统一观感，不随机混用强裁铺满与不同宽度的黑边。此默认取代旧的“不要自动添模糊背景/须先选择模糊补边”约定：集中需求稿告知默认即可，无需逐镜审批；用户已明确的其他策略优先，不能覆盖旧项目已确认构图或精修。

显示比例须考虑旋转、像素宽高比等有效显示信息。比例相同正常展示，不另添背景；仅像素分辨率不同（如1920×1080与3840×2160）不触发补边。全部源片比例彼此一致但不同于画布，仍适用默认。背景不等于改变前景比例，不强行拉伸或默认裁切前景填满；人物、文字、主体与隐私要求优先。

视觉目标统一，工程结构按目标软件/版本实现：保留独立可编辑的背景层/背景效果，复用原素材引用，使用目标支持的局部模糊与等比覆盖，模糊程度和相关变换保留可调。前景与背景逐镜源区间、成片时间、速度/时间映射一致，照片展示时长同步，运动/转场处检查露边和错位。PR、Resolve、FCP等不强套剪映的第一主轨、全片复制或复制画面不透明度0；同画幅段无需额外背景，剪映为主轨连续性复制全片是第4.2节特例。此处是输出要求，不声称各软件具体字段、效果或导入已验证。

Demo与工程使用同一适配意图，Demo允许渲染合成画面，但不得将其或预先放大/模糊另存的视频/图片作为工程背景替代。禁止会同时模糊前景的全局效果。两层原声按项目策略仅保留约定单份贡献，背景通常静音；背景连续可见内容遵守与前景相同的隐私边界，模糊不等于允许回露。隐私、格式或导出器能力不足时集中说明并确认替代，不静默退成黑边、强裁或烘焙背景。

验收按目标分别记录：结构配对/对齐及背景所需区间覆盖；实际画面中背景铺满、前景清晰无拉伸、无意外黑边/隐私回露/双播；编辑器内参数可调；保存关闭重开保持。外部Demo模拟不证明目标编辑器渲染成功，字段存在不证明界面可调；遵守第6节默认本地检查、按需最小界面验证，不为新默认常规接管电脑。沿用的剪映用户实测仅证明其已报告项目效果，不证明PR、Resolve、FCP或其他系统/版本已通过。交换格式未能保留背景时明确降级和待验项目，不用完整工程等表述掩盖缺项。

### 4.2 剪映特殊实现：连续双层素材＋底轨原生背景模糊

适用条件：目标为剪映，存在素材显示比例与画布不一致，采用第4.1节默认模糊补边或用户明确选择模糊补边；用户明确选择其他策略则不启用。本方案不限定Windows/Mac或画布方向，该规则独立于第3节Windows字段适配，不能因为现有组件只支持Windows就缩小方案范围。

剪映第一视频轨道（主轨/底轨）具有自动吸附、连续排列逻辑；不要仅在需要补边的时段零散铺背景，避免空档压缩后与前景错位。按以下结构输出：

1. 第一视频轨道完整复制清晰前景的全部镜头，包括与画布比例一致的镜头和照片，连续铺满全片，不只复制待补边镜头。不另存复制媒体文件，仍引用完整原素材。两层逐段一一对应，镜头顺序、源入出点、成片起止/时长一致；变速、照片展示时长及相关时间映射一致，不能只比片段数量或总时长。逻辑镜头ID在内部成对映射，复制片段使用各自必要唯一工程ID，不改变原素材引用与显示命名。
2. 第二视频轨道显示清晰前景。比例不一致的素材按项目约定保留主体及原始比例、等比适配，不强行拉伸或为了填满而裁切前景。底轨连续背景位于其下，不把两层顺序放反。
3. 第一轨使用剪映原生“背景填充—模糊”，由剪映按当前画布自动放大背景并填满；该轨清晰复制画面的不透明度设为0，仅显示原生模糊填充，第二轨正常显示清晰画面。模糊程度作为工程内可调整参数保留，不用全局模糊污染上层前景。须核实目标版本在复制画面不透明度0时仍保留原生填充；不能盲设alpha后就认定背景存在，也不能以手工放大素材冒充原生自动填充。
4. 不通过代码预先放大、模糊并另存视频/图片来替代可编辑背景。Demo可按相同视觉意图渲染，但Demo或外部渲染器的模拟效果不作为剪映原生背景已成功的证据，不以烘焙Demo代替工程。两层视频原声均依项目声音策略处理，只保留约定的单份原声贡献，背景复制层通常静音；不得双播或静默改变已确认混音。
5. 背景与前景遵守同一隐私边界。核查自动放大后实际可见内容及连续区间，不能因模糊、底层或引用完整原片就视为已获隐私许可；前景裁掉的人物/面部不能在背景重新出现。无法同时满足隐私和原生背景要求时排除该镜头或集中说明替代补边，不擅自放宽隐私、预烘焙或改用其他方案冒称本方案完成。

交付前分层验收：

- 结构检查：第一视频主轨从片头到片尾连续无空档、无意外重叠；两层全部镜头逐段比对原素材、顺序、源入出点、成片时间及时间映射；必要唯一ID和背景引用有效，不透明度/原声/模糊设置符合目标适配。人工策划的留白需保持双层同一时长，不留主轨自动压缩的洞，不能为凑连续擅改故事时间。
- 实际画面/渲染检查：模糊背景覆盖当前画布，比例不一致的素材无意外黑边，前景清晰、无拉伸且构图符合约定，两层切换同步、声音无双播、背景无隐私回露。区分外部预览模拟与剪映实际播放/渲染，首中尾和特殊比例/切换处按实际风险检查，隐私按连续入选区间核查。
- 编辑器参数及保存重开验收：确认原生背景类型和模糊程度能在剪映界面调整，并分项记录保存、关闭、重开后效果/对齐是否保持。JSON字段存在或结构通过不代表渲染、可调参数或保存重开通过；未知标待验，不补造验收。沿用第6节轻量检查、同版方法复用及按需最小界面样例原则，不要求Agent常规接管电脑。

用户在本项目实际检查后确认“连续双层素材＋底轨原生背景模糊”符合要求（2026-10-17本次反馈）。这是用户报告的方法效果证据；本条反馈未单列平台/版本及保存重开结果，不自动归入此前11.6.0.14552的其他方法验收，也不代表所有版本已通过。具体工程字段、原生背景与透明度作用方式需适配目标平台和版本；无法保留原生效果的交换格式/导出器须说明能力缺项或集中确认替代，不能静默烘焙。现有jianying_editable.py只检查登记、名称、源范围和片段变换，不负责生成/验证双层原生背景；其通过不能覆盖本节验收。

### 4.3 通用时间线与映射

统一事实来源至少记录：工程宽高/画幅、精确帧率、预览规格、总时长；稳定素材ID、源路径、类型、宽高/旋转/帧率/时长、Session；源入出点和成片入出点、轨道、速度；适配/裁切/位移/缩放及关键帧；音频源偏移、静音、增益/包络/关联；字幕文字、时间、类型、样式/位置；派生媒体到原片映射。

源in/out不是成片start/end。音频裁切传source_start，不默认源0秒。使用有理数或整数精度，输出边界按目标帧率量化，查累积误差；29.97不能当30。VFR必要时派生转码，原片只读，记录映射；无必要不全库转码。

照片展示时长非源时长；旋转、像素尺寸、显示比例一起判断。规范化构图意图由导出器转换成目标坐标/比例/关键帧插值，首中尾核查。预览渲染与工程共用这些决策。

旁白/BGM独立可编辑，原视频音可绑定或拆分，依精剪便利性，不强制全拆。静音/启用/增益/声道/源偏移保持，避免随视频和独立轨双播。仅供精剪保留的原声默认静音并说明。

字幕区分现代Caption、可编辑文字标题、烧录。SRT主要保留文字和时间，不保证样式。标题可编辑不冒充原生字幕轨，单独SRT不等于已嵌入工程。字号按实际视觉尺寸适配，不复制软件数值；全片检查长句、边界和不同底色可读性。

### 4.4 原生照片运动、转场与资源检查

在项目已授权的运动/转场范围内，优先用目标软件原生片段参数、关键帧和转场，保留完整原素材引用与界面可调整/删除能力；明确要求原生时不以加工图片、动态视频或扁平Demo替代。无对应能力时说明缺项并按既有降级约定处理，不冒充已实现，不为粗剪强行加效果。数量、幅度、持续时间依据主体、构图和节奏，不套项目案例配额。

结构检查涵盖关键帧时间/属性关联、转场边界与持续时间、必要源余量、效果资源及前后景关系，检查有无改变既定总长和声音/字幕位置。双层补边镜头核查两层时间、切换及合成结果；参数按各目标语义处理，不强求两层数值相同。普通媒体、原生效果文件、资源目录分类核查：目录检查实际需要的配置/场景资源及引用，不按普通视频解码，也不因是目录就跳过可用性检查。
